# Fabric服务器搭建：Java 装对、mods 放对、配置选对，新手也能把模组服跑起来

想搭 Fabric 服的人，卡点通常不在 Fabric 本身。Installer 双击、选 Server、点安装，这一套五分钟就能走完。真正让人卡住的是另外几件事：Java 版本装错了服务端直接报错退出；mods 文件夹里混进客户端 mod 导致开服崩在加载阶段；机器只有 2G 内存却想跑 200 个 mod 的整合包，进游戏后发现 TPS 只有个位数。

这篇按真实开服顺序把这些讲清楚，同时把机器怎么选、套餐差在哪、到底要花多少钱一起说完。

## 先把三个前提确认掉

在动手之前，有三件事决定了后面顺不顺。

**Java 版本必须跟 Minecraft 版本对上。** 这一条是新手翻车率最高的。Fabric Loader 本身很轻，但它启动时要靠对应版本的 JVM：

| Minecraft 版本 | 需要的最低 Java |
| --- | --- |
| 1.20.5 及以后 | Java 21 |
| 1.18 – 1.20.4 | Java 17 |
| 1.17.x | Java 16 |
| 1.16.5 及更早 | Java 8 |

注意这里说的是**最低**要求。装高版本 Java 跑低版本 MC 通常也能启动，反过来一定不行。Ubuntu 上装 Java 21 就一行：

bash
sudo apt update
sudo apt install openjdk-21-jre -y
java -version


只开服不用写代码的话，装 `jre` 就够，比 `jdk` 省几十兆空间。

**内存其实是按整合包算的，不是按人数算的。** 纯净服给 2G 能带十几个人；换成 200+ mod 的整合包，4G 起步是常态，8G 才比较从容。这个差异在选机器时比 CPU 更值得优先考虑。

**Fabric 对单核性能比对多核敏感。** MC 主线程基本吃单核，多核主要帮区块生成和 GC。同样是 4 核，主频 2.5GHz 的服务器和主频 5GHz 以上的服务器，同样的整合包体验差距是肉眼可见的。

## 手动搭建：从零把 Fabric 服务端跑起来

### 下载与安装

去 fabricmc.net 的下载页，选 **Minecraft Server** 标签页。你会拿到一个安装器（exe 或通用 jar 都行），跑起来后切到 **Server** 页签。

需要选的东西只有三样：Minecraft 版本、Loader 版本、安装目录。安装目录写一个不存在的文件夹名也没关系，它会自己建。点 Install 之后，它会提示你 **Download server jar** —— 这步别跳过，它下的是 Mojang 的官方原版核心，Fabric 需要它作为底座。

装完之后目录里大概是这样：


mc-server/
├── fabric-server-launch.jar
├── server.jar
├── libraries/
└── （首次启动后生成）eula.txt、server.properties、mods/


### 第一次启动和必改的两个文件

启动命令很简单，`-Xmx` 后面跟的是给服务端的内存上限：

bash
java -Xmx4G -jar fabric-server-launch.jar nogui


第一次跑一定会停，因为 Mojang 的 EULA 没同意。打开生成的 `eula.txt`，把 `eula=false` 改成 `eula=true`，再启动一次，看到 `Done (x.xxxs)! For help, type "help"` 就算起来了。

`server.properties` 里几个值得动的项：

- `online-mode=true` —— 正版验证开关。想让盗版客户端也能进就改 false，但服务器会失去 UUID 校验，玩家的物品和权限可能对不上，建议自己权衡。
- `view-distance` —— 视距，默认 10。这是性能开关里最有效的一个，模组服降到 5 到 6，TPS 能明显回升。
- `server-port` —— 默认 25565，需要对外说明的就是这个端口。

### mods 放对位置这件事

Fabric 服能跑的 mod 要看类型。给你三个判断标准：

- 装之前先看 mod 页面的环境标签。标 `Client` 的不要放进服务端，OptiFine 和 OptiFabric 就属于这一类，放进去必崩。
- 大部分内容型 mod（新生物、新维度、新物品）需要**服务端和客户端都装**，只装一边玩家进不去。
- 性能、备份、管理类 mod 大多是纯服务端的，玩家不用装。

另外，Fabric 生态里绝大多数 mod 依赖 **Fabric API**，这个 jar 也要丢进 `mods` 文件夹，忘了装会出现一堆加载失败报错。

排查崩溃有个笨但有效的办法：报错日志里通常有行标红的句子直接写了是哪个 mod 挂了，没有的话就一次移除一半 mod 二分查找。这一步没有捷径。

## 什么时候该放弃手动，直接上游戏面板

手动搭建的优点是可控，缺点是要自己管 Java 环境、自己备份存档、服务器挂了要登录 SSH 重启。如果你的目标是“和朋友一起玩”，而不是“把开服流程学一遍”，面板服能省掉其中大部分工作量。

这里就得说到雨云。它的游戏云产品线分成三种形态，针对的就是不同的动手意愿：

- **雨云面板** —— 自研面板，跑在 Kubernetes 集群上，支持一键开服、CPU 机型切换、可视化管理、备份和 MySQL，配置降级升级都能在网页里点。
- **MCSM 面板** —— 开源的 MCSManager，网页操作，支持 SFTP 传文件，教程资料最多。
- **游戏云 VPS** —— 给你一台完整的 Windows 或 Linux 机器，能装 MCDR、能挂机器人、能搞群组服，代价是开服经验得自己补。

对于 Fabric 服来说，一件挺关键的事是：雨云面板的一键开服列表里**直接包含 Fabric**，同时也覆盖 Arclight、Mohist、CatServer、Paper、Waterfall、BungeeCord 这些，以及基岩版、泰拉瑞亚和饥荒。也就是说你不用手动下载 installer、不用自己装 Java，选好版本点开机，服务端核心它就帮你拉好了。后面要加 mod，直接进面板的文件管理往 `mods` 里传就行。

当然，面板服也有边界。上面那套按 CPU 电量计费的模式，配在“一时兴起玩两小时”的场景里很划算；但如果你要做全天候大服、要跑群组架构、要自己深度改启动参数，还是 VPS 更合适。

## 开服后最容易撞上的几个问题

**服务端起来了但玩家进不去。** 先确认三件事：客户端 MC 版本和服务端一致（不一致会直接拦掉）、端口是 TCP 25565 且已经放行、`server.properties` 里的端口没被改过。如果用 NAT 共享 IP 机型，还要在面板里做端口映射，把内网 25565 映射到分配给你的对外端口，用映射后的地址连。

**TPS 一路往下掉。** 十有八九是视距和实体数量。把 `view-distance` 从 10 降到 5 到 6，关掉不必要的刷怪类 mod，效果最直接。

**玩家自己攒的房子加载后缺方块。** 一般是内存不够导致区块保存中断，`-Xmx` 加一点，或者装个分区块备份的 mod。

**模组服卡在加载界面。** 检查 `mods` 里有没有客户端专属 mod，以及 Fabric API 是否装上了。

## 几个常被问到的问题

**Fabric 和 Forge 该选哪个？** 看 mod。Fabric 加载更轻更快，很多性能优化类 mod（比如各类优化模组）只做 Fabric 版；Forge 和 NeoForge 的老牌大型整合包生态更全。如果目标整合包只出了 Forge 版，硬上 Fabric 是跑不起来的。

**32 位系统能开吗？** 别折腾了，现在主流 MC 版本需要 64 位 JVM。

**一定要用 Linux 吗？** 不。雨云游戏云提供 Windows 远程桌面机型，Fabric 在 Windows 上装法和 Linux 一样，只是资源开销大一些。纯开服场景 Linux 更省。

**2核4G 够开多少个 mod？** 按官方给出的承载基准，在 15 个 mod、视距 5 的条件下去估算，2核4G 属于小服起步档。想上整合包，直接往 4核8G 看。

一句话收尾：Fabric 服的开服流程本身不难，难点全在 Java 版本、mods 分类和机器档位这三个判断上。把这三样定下来，剩下的就是点按钮的事。
